# Demo script (2:00 hard cap)

Timed to the structure the competition asks for. Every line of on-screen text and every
number below is real — copied from an actual local run of the app while writing this
(see the walkthrough note at the end), not written from memory or imagination. Re-run it
yourself before recording to reconfirm exact numbers, since problems are randomly
generated and specific values (like pMastery percentages) will differ run to run even
though the behavior won't.

Record locally (`npm run dev`) with a real `GEMINI_API_KEY` in `.env` if you want live
Gemini text in the demo rather than the fallback templates — both work, and this
version of the script has actually been captured once with a live, unexhausted key
(see `screenshots/09-compare-synced-reveal.png`, which shows real "live Gemini
response" text), so seeing that fire during recording is a realistic thing to expect,
not just hoped for. If you hit quota, the fallback text is what recording without a
working key will show — don't fake having AI text that isn't there.

This is a rewrite of the original script to make room for what's shipped since it was
first written (a second subject, the embeddings similarity map, live camera capture,
Visual Proof diagrams, the report card, and `/compare`'s now-synced reveal) — something
had to be cut to fit inside 2:00, and the cut is the `/compare` segment's narration,
not its substance, since the synced reveal (both panels landing in the same beat) is
actually faster to watch than the old staggered version.

## 0:00–0:15 — The problem

Open `/`. Read the headline out loud as it's on screen, don't paraphrase it:

> "Most tutors trust a right answer. Misko checks if you earned it."

Follow with the subhead, also verbatim:

> "You can get the right number by luck, a memorized trick, or genuine
> understanding — and a normal quiz can't tell the difference."

That's the entire problem statement in two sentences someone else already wrote well.
Don't add narration on top of it.

## 0:15–0:30 — The big idea

Point at the homepage's live example card. Say, in your own words, something like:

> "Misko doesn't just grade the answer. When a correct answer looks
> shaky, it quietly gives a second, different problem to check — and only
> says something if the understanding didn't actually hold up."

Click into `/practice`.

## 0:30–1:15 — Live demo of the core mechanic (the wow moment — don't shorten this)

This is the confirmation-round mechanic end to end, exactly as it behaves:

1. **First problem** (order of operations): *"Evaluate: 2 + 6^2"*.
   Set confidence high, answer **64** (applying `+` before the exponent —
   a real, named misconception, not a random wrong number). Submit.
   Feedback names it specifically: *"It looks like your answer matches a
   common pattern: treats an exponent as if it applies after
   addition/multiplication rather than before, per standard precedence."*
   — say out loud: **this isn't a generic "wrong, try again."**
2. **Next problem**, same concept: *"Evaluate: 5 + 2^2"*. Answer correctly
   (**9**). Normal positive feedback — nothing unusual shown yet. Point out the
   Visual Proof diagram underneath it: a deterministic, non-AI diagram computed
   straight from the same numbers as the answer, not generated by a model.
3. **Next problem** looks completely ordinary but isn't: badge reads
   **"double-check"**, reason: *"Double-checking your last correct answer
   with a similar problem."* — point this out on screen, since it's easy to
   miss and it's the actual mechanic firing silently.
4. Answer this one **wrong too**, the same way (applying the exponent
   last again — e.g. **144** instead of 24 on *"Evaluate: 8 + 4^2"*). The
   response changes: `confirmationResolved: "caught"`, and the feedback
   adds a line naming the exact earlier problem: *"This double-checks an
   earlier correct answer to 'Evaluate: 5 + 2^2' — it didn't hold up."*
   **This is the moment to slow down on camera.** The system just proved,
   with a real second graded problem, that a "correct" answer two steps ago
   wasn't actually understood — not a guess, not a vibe.

Say directly to camera: *"It never accused anything off one answer. It
waited for a second, independently graded problem before saying so."*

## 1:15–1:35 — The personalization mechanism

Switch to `/compare`. It seeds two fictional learners with different recent
histories (Priya: recent negative-number sign errors; Marcus: recent
combining-like-terms exponent confusion) and submits the **exact same wrong
answer** to the **exact same problem** for both, through the real backend —
nothing scripted per-learner. Click "Reveal the difference" and watch both
panels land their diagnosis **in the same synced beat**, not one after another.
Point out that the diagnosis body is IDENTICAL for both (the same misconception,
correctly matched) — but only Priya's appends a second sentence connecting it to
her own recent history. Say, briefly:

> "Same wrong answer, same problem — the system responds differently because it
> actually knows something different about each of them."

## 1:35–1:45 — It's an architecture, not an Algebra app

Back on `/practice`, switch the subject tab from Algebra I to **Chemistry** live,
on screen — a real dimensional-analysis problem renders immediately. Say:

> "Same diagnosis pipeline, same mastery gate, same AI layer — no code path
> forked to add a second subject. Algebra was the proof of concept, not the
> ceiling."

## 1:45–1:57 — What the dashboard actually knows

Jump to `/dashboard` for whichever learner you were using in the first segment.
In order, point at:
- The mastery bar for order of operations — *"This is Bayesian Knowledge
  Tracing, not a streak counter. One slip lowers the estimate; it doesn't
  reset a progress bar to zero."*
- The confirmed/caught headline stat — the real numbers from the walkthrough
  above (**1 checked, 1 caught, 0 confirmed**), a persistent record, not a
  one-time popup.
- The misconception similarity map — *"A genuinely different ML technique
  from everything else so far: every misconception is embedded and laid out
  by how conceptually similar it is to the others, so a mistake can cluster
  with one from a completely different subject if it's really the same
  underlying error."*

## 1:57–2:00 — Final statement

> "Misko doesn't ask whether you got the answer right. It asks whether you'd
> get it right again."

## Notes on this script

- Every quoted line of app copy above was read directly off a real response
  from the running app (or, for the homepage, directly off `page.tsx`) while
  writing this file — none of it is invented dialogue. Exact numeric values
  (pMastery, specific wrong numbers used) will vary between runs because
  problems are randomly generated each time; the described *behavior*
  (misconception naming, the silent confirmation round, the caught reveal,
  the two-learners-diverge result, the synced `/compare` reveal, the live
  subject switch, the embeddings map) is deterministic and will recur exactly.
- If recording without a `GEMINI_API_KEY` (or with one that's hit quota),
  every line above still happens exactly as described — the rule-based
  confirmation trigger and the misconception-matching in this specific
  script don't require Gemini at all (see ARCHITECTURE.md "Catching the
  Correct Answer Trap"). What changes is the diagnosis text's tone/source,
  not whether the mechanic works.
- This script is tighter than the original to make room for the subject
  switch and embeddings map (new, highest-leverage additions per the
  project's own planning notes) while keeping the 0:30–1:15 mechanic
  completely untouched, since it's still the strongest single beat. Live
  camera capture and Visual Proof get a mention each but not a dedicated
  segment — there wasn't room for both without diluting the wow moment, and
  the mechanic demos better live than either of those two would on their own.
- **Rehearse this against a stopwatch before recording** — it's tighter than
  the original, which itself already ran close to 2:00, so pacing discipline
  matters even more this time. The competition's stated rule is that content
  past 2:00 isn't reviewed at all.
